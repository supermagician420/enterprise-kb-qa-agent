# 企业知识库问答助手（最小 RAG Agent）

## 项目是什么

这是一个模拟“企业知识库问答”的最小 RAG Agent：用关键词检索本地 FAQ、把命中段落拼进提示词再调用 LLM，专门用来练习 AI 应用的测试与兜底设计。

## 我怎么测的

我没有只跑正常问题，而是先按三类失败面主动构造输入，再用真实 CLI 子进程和本地 HTTP 故障桩复现：

- **知识库无答案，诱导幻觉**：不问知识库能完整回答的“请假流程”，而是问“病假提前几天”“加班有没有加班费”这类只沾到一半的问题，观察模型会不会用常识补全公司制度。
- **输入边界，制造脏输入**：直接回车提交空字符串；把一句报销问题重复到 40 万字符，观察脚本有没有空值校验和长度上限，还是会把超长 prompt 原样发给模型。
- **API 异常，固定错误现场**：用一个错误的 `LLM_API_KEY` 跑正常问题，同时用本地 HTTP 桩固定返回 401/400，避免把“网络偶发”误判成代码问题。

需要说明测试限制：当前本地没有 DeepSeek Key，幻觉两组是把脚本生成的同一 Prompt 交给一个公开 OpenAI 兼容模型跑出的，不能代表 `deepseek-chat` 的固定答案；边界和异常两组是真实 CLI + 本地桩，结果可复现。完整记录在 [TEST_REPORT.md](TEST_REPORT.md)。

## 我发现了什么

**1. 知识库没答案时，模型会补公司制度。**

输入：`加班有加班费吗？`

知识库只写了“加班调休需在 6 个月内使用”，没有说是否支付加班费、能不能结转。实际输出里，模型直接断言：

> 加班按公司规定不是以加班费方式补偿，而是采用「调休」的形式。

还补出了“调休如果未在规定时间内使用，就会失效，不能结转”“超过三天需要部门负责人和 HRBP 的批准”等知识库里没有的规则。相近的 `病假需要提前几天申请？` 虽然没有编出天数，但也把“资料未提及”说成了“没有硬性规定”，并补了一句知识库没有的“提交后请把病情说明或需要请假的原因写清楚”。这说明检索 0 分时仍返回段落、提示词又没有拒答约束，模型只能靠自觉。

**2. 空输入和超长输入都没有本地拦截。**

空输入直接回车时，检索仍返回《请假流程》《报销规则》，HTTP 桩收到 `question_chars=0`、`prompt_chars=264` 的请求，脚本退出码 0，相当于让远端模型猜一个空问题。stdin 直接关闭、没有换行时，则抛出未捕获的 `EOFError`，退出码 1。

把 `请说明报销流程。` 重复到 40 万字符后，脚本拼出 `prompt_chars=400264` 的请求并发送；故障桩按上下文超限返回 400，脚本抛出 `urllib.error.HTTPError: HTTP Error 400: Bad Request`，退出码 1，终端显示完整 traceback。

**3. API 认证失败不是提示，是 traceback。**

输入正常问题 `IT报修多久响应？`，把 `LLM_API_KEY` 改成错误值，脚本先打印检索片段，随后抛出：

```text
urllib.error.HTTPError: HTTP Error 401: Unauthorized
```

退出码 1。用户看不到“Key 无效，请检查配置”，只能看到 Python 堆栈；`call_llm()` 里没有任何 `try/except`。

## 我做了什么修正/兜底

这版没有改原始脚本：里面的缺陷是刻意保留的测试靶子，改掉就失去了这轮测试对象。下面是我认为应该补的兜底，不是已经上线的实现。

如果我要修复，我会先做三件事：

- **检索为空或相关度不够时，强制不调用模型**：给关键词得分设阈值；`retrieve()` 没有命中、或最高分低于阈值时直接返回“知识库中未找到依据，建议联系 HR/IT/财务确认”。即使有段落，也要在提示词里写死“只能依据资料回答；资料不足必须明确说不知道，不得补全公司制度”。
- **输入先过本地校验**：`strip()` 后空字符串直接拒绝；设置合理长度上限，超长时明确提示“问题过长，请精简后重试”，而不是静默截断或原样发给 API。
- **API 异常统一收口**：用 `try/except` 包住 `urlopen`、HTTP 错误、超时、JSON 解析和响应字段读取；技术细节写日志，用户只看到可读提示，例如“AI 服务暂时不可用（401，请检查 API Key）”，而不是崩溃堆栈。API Key 为空时也应在发请求前就报配置错误。

## 和我方向的关系

这个项目对应企业 AI 对接/实施场景中常见的知识库问答落地与质量兜底问题。
